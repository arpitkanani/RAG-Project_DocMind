DocMind update report
Date: 2026-07-05

What I changed

Task 1: anti-hallucination prompt and citations
- Root cause: the QA prompt was too loose for a small local model and only asked for a generic source mention, which made it easier to drift outside context and harder to cite YouTube timestamps.
- Fix:
  - Rewrote the QA prompt in `src/chains/qa_chain.py` to force context-only answers, require the exact refusal string when unsupported, and prefer short paragraph plus optional bullets.
  - Added citation-aware context formatting for filename/page, row, and YouTube transcript timestamps.
  - Changed YouTube loading to keep transcript segments with timestamps instead of flattening everything into one long string.
- Verification:
  - `python -m py_compile app.py src\exception.py src\chains\qa_chain.py src\pipelines\qa_pipeline.py src\components\memory_manager.py src\components\retriever.py src\components\vector_store.py src\components\document_loader.py src\utils\youtube_helper.py`
  - Live model verification was blocked in this shell because the active Python runtime is missing app dependencies such as `langchain-chroma` and `fastapi`.

Task 2: unhashable type: 'slice'
- Exact root cause: `/query` in `app.py` logged `result[:200]` even though `result` is a dict, which triggers `TypeError: unhashable type: 'slice'`.
- Fix:
  - Replaced the bad slice-based logging with structured logging against dict fields.
  - Added explicit query error handling so collection failures return clean JSON instead of bubbling raw exception text.
- Verification:
  - Root cause confirmed directly from the route implementation.
  - Route now logs `session_id` and `collection_scope` instead of slicing the response object.

Task 3: cross-document query bug
- Root cause: the frontend stored only one active collection in `state.collection` and overwrote it on every new upload, so later queries silently targeted the most recently uploaded document.
- Fix:
  - Frontend now tracks a list of attached document chips and sends `collection_names` to `/query`.
  - Backend pipeline/retriever now accept multi-collection scope and merge across those collections.
  - Session state now stores attachments so switching chats restores the correct collection scope instead of silently falling back to "last uploaded".
- Verification:
  - Code-path review confirmed queries are now scoped from upload -> session attachment state -> `/query` request -> `QAPipeline` -> `Retriever`.

Task 4 and Task 5: deleted collection and stale session handling
- Root cause: deleted or stale collection names were not validated early, so failures collapsed into generic exceptions and surfaced in the UI as if the AI had said them.
- Fix:
  - Added `CollectionNotFoundError` and `KnowledgeBaseEmptyError`.
  - Retriever/vector-store validation now raises clean typed errors for missing collections.
  - `/query` now returns a structured 404 JSON payload with `error_code = collection_not_found`.
  - Frontend now intercepts that error code and shows: "This document was removed. Please upload a document to continue."
  - Session attachment metadata is preserved, so older sessions remain identifiable, but stale collection queries now fail gracefully instead of crashing.
- Verification:
  - Error-handling paths are implemented end-to-end in backend and frontend code.

Task 6: cleanup and endpoint coverage
- Cleaned leftover summary/quiz intent flow from the active frontend JS and updated the landing page copy to match the current RAG-only product.
- Kept multi-session support because it was fixable and is now explicit via per-session attachment state. I did not remove it.
- Added `POST /sessions` and `DELETE /sessions` so the session API is more complete while keeping `/sessions/new` for compatibility.

Environment limitation during verification
- The active interpreter in this workspace is missing runtime packages required to boot the app (`fastapi`, `langchain-chroma`, and related stack), so I could not complete a live end-to-end HTTP run from this shell.
- I added `endpoint_regression_check.py` as a lightweight regression harness for a proper environment; it exercises the route logic with stubs once dependencies are available.

Latest follow-up adjustments
- Replaced the LangChain `MergerRetriever` dependency with an internal multi-collection retrieval flow in `src/components/retriever.py`, so uploading a second file no longer depends on optional package internals.
- Tuned retrieval defaults in `config/config.yaml` for tighter factual lookup:
  - temperature `0.5`
  - chunk size `500`
  - overlap `80`
  - retriever mode changed from `mmr` to `similarity`
  - top-k reduced to `4`
- Relaxed the QA prompt in `src/chains/qa_chain.py` so answers are less robotic, avoid phrases like "the transcript says", and allow grounded YouTube summaries when the user asks what a video is about.
- Frontend generic 500 failures now show a simple toast: "Server is down. Please try again." instead of rendering raw backend error details in chat.
